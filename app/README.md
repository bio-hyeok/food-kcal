# food-kcal 모바일 앱

음식 사진을 고르면 음식을 자동으로 찾아 후보를 보여주고, 먹은 양을 고르면 칼로리를 보여주는 앱입니다. Expo(React Native)로 만들었습니다.

## 지금 되는 것

- 갤러리/카메라로 사진 고르기 → **사진 속 음식을 하나씩 찾아** 사진 위에 번호 상자를 그림 (한 사진에 여러 음식, 2026-11 추가)
- 음식마다 카드: 후보 5개(이름, 신뢰도), 인식에 성공한 음식은 **1순위를 미리 골라 1인분 칼로리를 바로 표시**
- 후보를 눌러 바꾸기, 인분(0.5/1/1.5/2) 또는 g 으로 양 바꾸기, 삭제
- 맨 위에 **합계** 칼로리·탄수화물·단백질·지방·나트륨
- 못 찾은 음식은 음식 이름 검색에서 눌러 목록에 추가
- 음식을 하나도 못 찾으면(음식이 아닌 사진 등) "음식을 찾지 못했어요" 안내 후 검색으로 연결

## 과제 시연용 구조 (위키 설계와 다른 점)

```
앱 ──사진──▶ 추론 서버 POST /detect ──▶ 음식마다 위치(상자) + 후보 foodId + 신뢰도
 └─ 영양정보는 앱 안의 src/foods.json 에서 찾는다
```

위키 설계는 `앱 → API 서버 → 추론 서버 + DB` 이다. 이번 과제는 배포하지 않고 `develop` 에서 돌아가는지만 확인하므로 **API 서버를 건너뛰고 앱이 추론 서버를 직접 부른다.** 로그인, 식단 저장, 통계는 없다. API 서버를 만들면 `src/recognize.js` 만 `POST /images`, `/recognitions` 로 바꾸면 된다.

## 실행 (시연 순서)

### 1. 추론 서버 켜기

모델 파일(`classifier.onnx`, `model_meta.json`)은 Git 에 없다. `ml/scripts/export_onnx.py` 로 만든 폴더를 `MODEL_DIR` 로 준다. 자세한 내용은 [server/inference/README.md](../server/inference/README.md).

```powershell
cd server\inference
$env:MODEL_DIR = "C:\food-data\models_v3"
$env:DETECT_MODEL_DIR = "C:\food-data\detector_v1"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8100
```

- `DETECT_MODEL_DIR`(검출 모델)을 빼고 켜면 앱은 예전처럼 **사진 전체로 한 음식만** 인식한다 (`/predict`). 상자는 그리지 않는다.

- `--host 0.0.0.0` 은 휴대폰에서 접속하기 위해서다. PC 웹으로만 볼 때는 `127.0.0.1` 이어도 된다.
- 처음 켜면 **Windows 방화벽 허용 창**이 뜰 수 있다. 휴대폰으로 시연하려면 "개인 네트워크"만 허용한다.
- 켜졌는지 확인: 브라우저에서 `http://localhost:8100/health`

### 2. 앱 켜기

```bash
cd app
npm install
npx expo start
```

- **PC 웹으로 보기**: 터미널에서 `w` 를 누르거나 `npx expo start --web`. 앱은 `http://localhost:8100` 으로 서버를 부른다.
- **휴대폰(Expo Go)**: QR 코드를 스캔한다. PC 와 휴대폰이 **같은 Wi-Fi** 여야 한다. 앱은 Expo 개발 서버가 도는 PC 의 IP 로 서버를 찾는다 (예: `http://192.168.0.5:8100`).
- 서버 주소를 직접 정하려면 `app/.env` 에 적는다 (`.env` 는 Git 에 올리지 않는다).

  ```
  EXPO_PUBLIC_INFERENCE_URL=http://192.168.0.5:8100
  ```

### 3. 사진으로 확인

1. "갤러리" 또는 "카메라"로 음식 사진을 고른다. 여러 음식이 함께 찍힌 사진도 된다.
2. "음식을 찾는 중이에요…" 뒤에 사진 위에 번호 상자가 그려지고, 아래에 **합계**와 번호별 카드가 나온다.
3. 확실한 음식은 1순위가 미리 골라져 있다. "확실하지 않아요" 카드는 후보를 눌러 고른다.
4. 인분이나 g 을 바꾸면 그 음식과 합계를 다시 계산한다. 틀린 음식은 삭제하고, 빠진 음식은 검색에서 눌러 추가한다.

연결이 안 되면 화면에 "인식 서버에 연결하지 못했어요 (주소)" 가 나온다. 서버가 켜져 있는지, 같은 Wi-Fi 인지, 방화벽을 허용했는지 확인한다.

## 알아 둘 점

- 모델은 304종만 안다. 김치, 나물, 회, 떡 등 원천 이미지가 없던 96종은 후보에 나오지 않으니 검색으로 고른다.
- test 1,520장(서버 코드로 측정): 음식을 찾아 잘라 분류하면 1순위 82.6%, 후보 5개 안 95.8% (사진 전체로 분류하면 74.5%). 음식이 아닌 사진은 86% 를 걸러 낸다 (`server/inference/README.md`).
- 검출 학습 사진은 거의 모두 음식이 하나라, 여러 음식이 함께 찍힌 사진의 정확도는 재지 못했다. 사진이 작거나 흐리면 음식마다 잘라 낸 부분이 작아져 정확도가 크게 떨어진다 (여러 음식을 이어 붙인 시험 사진에서 확인).
- 번호는 검출 신뢰도 순서다 (왼쪽→오른쪽 순서가 아님).
- 칼로리는 AI-Hub 영양DB의 한 접시 기준 값이다.

## 테스트

```bash
npm test
```

칼로리 계산(`src/calc.js`), 영양 데이터 형식, 인식 응답 처리(`src/recognize.js`), 음식 목록·합계(`src/meal.js`)를 확인한다. 계산 규칙은 위키 [ERD 설계 문서](https://github.com/bio-hyeok/food-kcal/wiki/ERD-설계-문서) 4절을 따른다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `App.js` | 화면 하나 (사진·상자 → 합계 → 음식별 카드 → 검색으로 추가) |
| `src/recognize.js` | 추론 서버 주소 정하기, 사진 보내기(`/detect`, 없으면 `/predict`), 응답을 음식 데이터와 묶기 |
| `src/meal.js` | 한 사진의 음식 목록: 1순위 자동 선택, 후보 바꾸기, 양, 삭제, 추가, 합계 |
| `src/calc.js` | 칼로리 계산 |
| `src/foods.json` | 음식·영양 데이터 400종 (AI-Hub 74번 영양DB). 직접 고치지 말고 `ml/scripts/build_foods_json.mjs` 로 다시 만든다 |
| `src/foods.sample.json` | 계산 테스트용 샘플 11개 |
